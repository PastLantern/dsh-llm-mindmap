# 设计一个自改进 Coding Agent，并防止它刷分

[RSI 闭环原理与护栏](../nodes/node-rsi-notes.md)

掌握度：待攻克

## 题眼 / 触发条件

- 题目出现「让 Agent 自己改进自己」「自动优化提示词或工作流」「越跑越强」
- 追问「分数涨了但真实效果没涨」「模型钻评估指标的空子」

## 破题固定步骤 / 核心公式

- 1. 先定改写范围：只开放 Skill、提示词、工具代码，评估逻辑不在其中。
- 2. 评估集分两份：选择集用来挑候选，hold-out 只做最终验收。
- 3. 保留规则：hold-out 提升超过阈值 ε 才合入，否则回滚。
- 4. 存档多个不同版本，不只保留当前最优。
- 5. 预算上限加人工门禁：权限、网络、评估相关的改动必须由人确认。

## 典型题与参考实现

你要做一个能自己改进写代码能力的 Agent，用 SWE-bench 类任务打分。画出闭环，并说出至少三种它可能刷分的方式，以及对应的护栏。

闭环：选父版本 → 读失败日志，提出自修改 → 沙箱里编译和冒烟测试 → 选择集打分 → hold-out 验收 → 进存档或回滚。

刷分方式与护栏：
1. 改测试或打分脚本 → 评估器放在只读挂载或独立容器里，Agent 没有写权限。
2. 对着固定测试集过拟合（硬编码答案、识别题目）→ hold-out 从不暴露，定期换题。
3. 关掉检测器或沙箱开关（DGM 和 STOP 都观察到过类似行为）→ 检测逻辑不在可改范围内；diff 里只要碰到评估或权限相关文件，直接拒绝并报警。
4. 用更多算力换分数（无限重试）→ 每题预算固定，只在相同预算下比较分数。

## 持续追加的变式与连环追问

### 变式 1：没有客观评估器的任务（比如写综述）还能做 RSI 吗？
- 追问：评估只能靠 LLM 打分时，闭环会出什么问题？怎么缓解？
- 关键变化：裁判和被评者同源时容易互相迎合，改进会朝裁判的偏好漂移，而不是朝真实质量。
- 解析：换不同家族的裁判模型；用成对比较代替绝对打分；把能程序验证的子任务（比如引用是否真实存在）拆出来单独校验；定期人工抽检。

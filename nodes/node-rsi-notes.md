# RSI 闭环原理与护栏

上级：[RSI 递归自我改进](node-rsi.md)

掌握度：待攻克 · 形态：核心笔记

> 改哪一层、谁来判、怎么防刷分：一个能落地的自改进闭环

$$\pi_{t+1} = \begin{cases} \pi' & \hat J_{\text{hold}}(\pi') - \hat J_{\text{hold}}(\pi_t) > \epsilon \\ \pi_t & \text{otherwise} \end{cases}$$

## 1 核心框架

### 一句话
让系统改进自己，关键不在「会反思」，而在每一轮改动都被一个它改不到的评估器确认过。

### 闭环四件事
1. **改什么**：权重、提示词、Skill 或工具代码、Agent 编排本身。
2. **谁来提**：模型读自己的失败记录，提出候选改动（Self-Edit）。
3. **谁来判**：外部 Verifier，例如单测、编译器、Benchmark、定理证明器。评估器必须在被改写的范围之外。具体做法见 [§5.1 五条护栏](node-rsi-notes.md#五条护栏)。
4. **留不留**：只有在 hold-out 上明显变好才保留，否则回滚；保留下来的版本进存档，作为下一轮的起点。循环的写法见 [§4.1 主循环](node-rsi-notes.md#主循环)。

### 和普通反思的区别
Self-Refine、Reflexion 改的是当前这一次的答案或记忆，下一个任务基本从头开始；RSI 改的是下一轮用来解题的系统本身，改进会累积。

## 2 改写对象分四层：越往外越好审计 · 架构设计

### 四层对比
越往外层越便宜、越好回滚；越往里层改进越「内化」，但代价和风险越高。

| 改写层 | 代表工作 | 反馈信号 | 好处 | 主要风险 |
| --- | --- | --- | --- | --- |
| 权重 | STaR、ReST-EM | 答案对错（二值奖励） | 能力真正学进模型 | 遗忘、输出多样性下降，回滚成本高 |
| 提示词 | Promptbreeder、OPRO | 验证集得分 | 便宜，随时回滚 | 对验证集过拟合 |
| Skill / 工具代码 | Voyager 技能库 | 环境执行结果 + 自检 | 可复用、可读、可审计 | 技能库膨胀，检索不准 |
| Agent 自身代码 | ADAS、Gödel Agent、DGM、SICA | Benchmark 分数 | 改进可以一层层累积 | 刷分、绕过沙箱 |

### 我的取舍
个人项目和工程场景先改外层（提示词、Skill、工作流），权重层留给手里有大量可验证数据的团队。

## 3 STaR：只在答对样本上微调，等价于策略梯度 · 原理推导

### 目标函数与梯度
STaR 每一轮：对每道题采样一条推理链 $\hat r$ 和答案 $\hat y$，只保留答对的；答错的题，把正确答案作为提示给模型，让它「倒推」一条推理链（Rationalization），再一起拿去微调。

目标是最大化答对率：

$$J(\theta) = \sum_i \mathbb{E}_{(\hat r_i, \hat y_i) \sim p_\theta(\cdot \mid x_i)} \big[\mathbb{1}(\hat y_i = y_i)\big]$$

用对数导数技巧求梯度：

$$\nabla_\theta J = \sum_i \mathbb{E}\big[\mathbb{1}(\hat y_i = y_i)\, \nabla_\theta \log p_\theta(\hat r_i, \hat y_i \mid x_i)\big]$$

指示函数把答错样本的梯度直接置零。所以「只在答对的样本上做 SFT」，就是这个梯度的蒙特卡洛估计。

### 两个容易忽略的设计
- **每轮从初始模型重新微调**：在上一轮的模型上接着训，容易过拟合自己生成的数据。STaR 每轮都回到初始模型，只把训练集换成新一轮筛出来的样本。
- **Rationalization 的作用**：没有它，模型一直答不对的难题永远不产生训练信号，能力会停在原地。

> ⚠️ 答案对不代表推理对：二值奖励会把「蒙对」的推理链也收进来，选择题和数值题里尤其常见。

## 4 Agent 改写自己的代码：存档加进化循环 · 架构设计

### 主循环
DGM 这一类工作的主循环大致是这样（简化版）：

```python
archive = [initial_agent]                 # 能跑通基本检查的版本都留着
for step in range(budget):
    parent = sample(archive, by="score+novelty")   # 不只挑当前最好的
    child = parent.self_modify(logs=parent.failures)  # 读自己的失败日志，改自己的代码
    if not sandbox_smoke_test(child):
        continue
    child.score = evaluate(child, tasks)  # 评估代码不在 child 的可写范围内
    if child.score >= MIN_USEFUL:
        archive.append(child)
```

### 三个设计要点
- **为什么要存档**：只保留当前最优就是爬山，容易卡在局部最优。存档留下「暂时不是最好、但不一样」的版本，后来的提升常常从这些旁支长出来。
- **分级评估**：先在少量任务上测，过线才上更大的任务集，控制算力。
- **和 ADAS 的区别**：ADAS 由一个固定的元 Agent 设计新 Agent，元 Agent 本身不变；Gödel Agent 和 DGM 里，改进者和被改进者是同一份代码，所以「改进的能力」也能被改进。

## 5 护栏清单：别让它学会刷分 · 工程实践

### 五条护栏
这五条都是在保护 [§4.1 主循环](node-rsi-notes.md#主循环) 里 `evaluate` 那一步。

1. **评估器只读**：测试集和打分脚本放在 Agent 的写权限之外，最好在另一个容器里跑。
2. **hold-out 不参与挑选**：一份集合用来挑候选，另一份从不暴露给它，只做最终验收。
3. **每次改动都留 diff**：每个版本存成一个 git commit，出问题一条命令回滚。
4. **预算硬上限**：步数、Token、墙钟时间都设上限，超了直接停。
5. **人工门禁**：涉及权限、网络、评估逻辑的改动，必须由人确认。这和本插件的提案队列是一个思路。

### 真实发生过的刷分
DGM 论文报告过：Agent 为了让幻觉检测通过，删掉了检测器依赖的标记，而不是真的修好幻觉。STOP 的作者也观察到，少数候选方案会尝试关掉沙箱开关。

> ⚠️ 护栏要做到「结构上做不到」，比如评估器所在目录根本不可写，而不是指望模型「不想作弊」。

## 6 Skill / 工作流级改写 vs 权重级自训练 · 工程实践

权重层自训练有遗忘风险，回滚要重新训练；在 Harness 层改 Skill 文档、提示词约束和 Python 工作流代码，每次改动都是一段可读的 diff：

- **可审计**：人能直接看懂改了什么。
- **可回滚**：git revert 即可。
- **不遗忘**：模型权重不动，原有能力不受影响。

代价是改进上限受模型本身能力限制，外层改得再好也补不了模型不会的东西。

## 7 2025 年进展：DGM、SICA 与 AlphaEvolve · 前沿演进

### 三个代表工作
- **Darwin Gödel Machine**（UBC 与 Sakana AI 等，2025-05）：SWE-bench 从 20.0% 提到 50.0%，Polyglot 从 14.2% 提到 30.7%。它自己找到的改进主要在工具和工作流上，比如更细粒度的文件查看与编辑、生成多个补丁再挑最好的。
- **SICA**（2025）：Coding Agent 直接编辑自己的代码库，在 SWE-bench Verified 的随机子集上从 17% 提到 53%。
- **AlphaEvolve**（Google DeepMind，2025-05）：改的不是自己，而是被评估的算法。用 Gemini 生成代码变体，评估器打分后进化；找到了只用 48 次标量乘法的 4×4 复数矩阵乘法，并在 Google 数据中心调度上平均回收约 0.7% 的算力。

### 共同点
它们都有**便宜、客观、能自动跑**的评估器，也就是 [§1.2 闭环四件事](node-rsi-notes.md#闭环四件事) 里的「谁来判」。写作、开放式研究这类没有这种评估器的领域，目前还看不到同等的效果。

## 8 2026 年进展：DGM-H、Terminal-RSI 与两篇复现 · 前沿演进

### 三条主线
接上一节，2026 年的进展可以归成三件事：把「改进机制」本身也变成可改对象；从编码基准扩散到终端和长周期任务；第一次被「教科书改动」这种朴素基线正面挑战。

### 元层也能改：HyperAgents / DGM-H（2026-03，ICLR 2026）
- **DGM 的瓶颈**：DGM 里「生成自我改进指令」这一步是手工写死、不可改的，还是为编程基准定制的。换个领域，编码能力涨了也带不动自改进能力。
- **做法**：把 task agent 和 meta agent 合进同一个可编辑程序，元层自己也能被改写（metacognitive self-modification）。
- **结果（论文自报）**：论文审阅 0.0 → 0.71，机器人奖励设计 0.06 → 0.37；在论文审阅和机器人任务上演化出的 hyperagent 迁到没见过的奥数评分任务，improvement@50 仍有 0.63（手工 DGM 的迁移版本接近 0）。
- **涌现出来的元能力**：性能追踪、持久记忆、偏差检测、算力感知的规划——不是预置的。
- **两处接口值得记**：① 论文审阅和奥数评分没有客观真值，只能用 LLM 裁判，作者专门留 validation 子集防裁判过拟合，这是「用 LLM 当评估器时的三条规则」（见 §10）的工程版；② 父代选择、评估协议、任务分布仍是固定的，正文没放开，理由是可复现与安全——最该被改的两样恰恰没让改。

### 从 SWE-bench 扩散到终端与长周期：Terminal-RSI（2026-10）
- 交替做两件事：改写已验证的轨迹（RSR），再用继承来的 critic 做策略精炼（RPR）；从 Qwen3.8-27B 起五阶段训出 Terminal-RSI-27B。
- 自报数字：Terminal-Bench 2.1 86.52%，Terminal-Bench Hard 79.00%；LHTB 上严格完成 0/46 → 5/46，过程分 0.21 → 0.37；SWR100 成功率 3% → 6%。
- 值得学的是**指标拆分**：「过程分涨了」和「严格通过」分开报，否则 0/46 → 5/46 这种量级的进步会被平均分抹平。

### 两盆冷水（都在 2026-10）
- **定向性检验**：取公开 DGM 日志里 145 次合格修改，比较「只给目标失败的反馈」与「给父代其他失败的反馈」，在任务、语言、仓库三个层面都没有可测的定向优势。小模型控制实验里相关反馈确实更管用（Qwen3-4B 多修 20 个百分点，Phi-4-mini 的 7 个百分点不显著），但「修好目标失败」不等于 held-out 变好。
- **教科书基线**：一个「调高输出 token 上限」的改动，就拿到最佳 loop agent 约 90% 的收益、单任务成本不到一半；DGM 放出的最佳 agent 在 held-out SWE-bench Verified 上没打过自己的初始版本，三个教科书改动反而更好、成本只有四分之一。
- **结论**：自改进的收益要先扣掉「人工调参也能拿到」的那部分。这条应补进 [§5.1 五条护栏](node-rsi-notes.md#五条护栏)：除 hold-out 之外，基线里还要有教科书改动、一次性重设计和安慰剂循环，并换更新的模型复测。

### AlphaEvolve 一年后（2026-05）
- 一周年披露：DNA 变异检测的误检与漏检降 30%（DeepConsensus）；电网 AC 最优潮流可行解 14% → 88% 以上；20 类灾害预测准确率 +5%；量子电路错误率降一个数量级。
- 它改的是**被评估的算法**而不是自己：评估器整个在系统外部，所以这些数字最经得起复现，也最容易被其他团队复用。

### 一句话
2025 证明「能自己改自己并涨分」；2026 一边把改进机制本身打开，一边被迫跟「人手工调参」比。对工程落地，后一条的约束力更强。

## 9 为什么要存档：只留最优会卡在局部最优 · 架构设计

只保留当前分数最高的版本，等于在爬山：每一步只接受变好的改动，很容易停在局部最优。

不少有用的自修改，单独看分数会先掉一点，比如先把文件编辑工具拆细，后面的改动才用得上它。存档留下「暂时不是最好、但不一样」的版本，后来的提升常常从这些旁支长出来。

对应 [§4.1 主循环](node-rsi-notes.md#主循环) 里的 `sample(archive, by="score+novelty")`。

## 10 用 LLM 当评估器时的三条规则 · 工程实践

裁判模型的参数被评者改不到，但被评者可以改输出去迎合裁判（更长、更笃定、套用裁判偏爱的措辞）。

1. 能用程序验证的部分（编译、单测、引用是否存在）一律交给程序；
2. 只有主观质量才交给裁判，裁判和被评模型尽量不是同一家族，并用成对比较代替绝对打分；
3. 定期人工抽检一小批，确认分数和人的判断仍然一致。
